# Observations & Limitations

This document records empirical findings about the prototype. Numbers should
be regenerated by running `python -m server.eval.run_eval` after adding
fixtures + golden files in `server/eval/`.

## Coverage matrix (design-time)

| Format | Adapter path | OCR? | Notes |
|---|---|---|---|
| Born-digital PDF | docling | no | Primary path, fastest |
| Scanned PDF / image-only PDF | docling (Tesseract) | yes | Latency dominated by OCR |
| Form PDF (multi-column / tables) | docling + pdfplumber augment | maybe | Quality gate triggers pdfplumber when no tables found |
| Empty/zero-text PDF | docling → pdfminer fallback | maybe | pdfminer rescues malformed PDFs |
| DOCX | docling | no | Native format support |
| PPTX | docling | no | Each slide → page |
| XLSX | docling | no | Sheets become tables |
| HTML / Markdown | docling | no | Trafilatura available as future enrichment |
| PNG / JPEG / TIFF | docling (Tesseract) | yes | OCR mandatory |
| `.doc` / `.rtf` / `.eml` / `.msg` | **unsupported** | n/a | Future work via subprocess |

## Per-extractor priors (initial)

| Extractor | Prior | Rationale |
|---|---|---|
| regex | 0.95 | Deterministic, type-validated |
| table | 0.85 | High when tables are detected |
| llm | 0.85 | Strong but non-deterministic |
| spatial | 0.80 | Reliable when bboxes exist |
| keyword | 0.75 | Brittle on tables/multicol |
| ner | 0.70 | Generalizes broadly but coarse |

These are seeds — recalibrate from eval-harness F1 numbers.

## Cold-start

- Docling layout/table model weights download on first run. With the Docker
  prewarm step, first **request** is fast; without it, expect ~30–90 s first
  parse on CPU.
- GLiNER weights (~hundreds of MB) download on first NER call. Same mitigation.
- Set `ENABLE_NER=0` to bypass GLiNER entirely.
- Set `ENABLE_LLM=0` (or omit `OPENROUTER_API_KEY`) to bypass LLM stages.

## Known limitations

1. **Voting priors are heuristic.** They were chosen by intuition, not
   measurement. A real corpus + the eval harness should drive these.
2. **No table extractor for borderless tables.** pdfplumber's table detector
   prefers ruled tables; Docling's is more robust but still misses some.
3. **NER labels in extractor mode** are derived directly from schema field
   names. If a discovered field name like `effective_date` is not a natural
   NER label, recall drops. Future: synonyms map for NER labels.
4. **OCR backend is Tesseract** — adequate, not state-of-the-art. For higher
   accuracy on tough scans, drop in docTR (Apache-2.0) as a second adapter.
5. **No streaming / async per-page parsing.** Whole document is parsed
   in-process; very large PDFs (>200 pages) may exceed memory budgets.
6. **Element list is capped at 500** in the response to keep payload size
   reasonable; `elements_truncated: true` in the response signals overflow.

## Filling out the eval harness

Drop a fixture into `server/eval/fixtures/<name>.<ext>` and a sibling
`server/eval/golden/<name>.json`:

```json
{
  "expected_doc_type": "invoice",
  "fields": {
    "invoice_number": "INV-2024-001",
    "total": "$1,234.56",
    "invoice_date": "2024-01-10"
  }
}
```

Run:

```bash
python -m server.eval.run_eval --out server/eval/results.json
```

The script prints per-fixture precision/recall/F1 and the chosen extractor
sources per field. Use those numbers to retune extractor priors and to
populate the empirical section of this document.

## Quick-start verification (manual)

```bash
# health
curl -s localhost:8000/health | jq

# PDF
curl -s -F file=@server/parser/input-files/sample_invoice.pdf \
  localhost:8000/api/parse | jq '.fields | keys, .document.parse_method'

# DOCX
curl -s -F file=@server/parser/input-files/cap.docx \
  localhost:8000/api/parse | jq '.document.parse_method, .schema[0:3]'
```
